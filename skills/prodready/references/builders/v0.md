# v0

What this covers: what v0 projects look like and what to check first.
Read it when: `builder: v0` is detected.
After reading you can find the data access code fast and explain how to apply fixes without the builder overwriting them.
Last checked: 2026-11-13. Detection of v0 projects is a heuristic; confirm before relying on it.

## What this builder generates
A Next.js App Router project with shadcn/ui components and builder metadata.

## What it tends to get right
Polished UI components.

## What it tends to leave unsafe
No auth or data layer by default, so what the user adds on top is often unprotected route handlers and server actions (AUTH-002, API-010); default metadata (LAUNCH-001).

## Where things live
`app/`, `components/ui`, `lib/`.

## Getting the code and backend under the owner's control (DEP-011)
Sync to GitHub and deploy from your own account. <!-- unverified -->

## Builder-specific cleanup (LAUNCH-005)
Replace default metadata and project names.

## How to apply fixes
Edit in the repository.

## Prompts the owner can paste into the builder
"Add a session check to every route handler and server action and return 401 when missing."
